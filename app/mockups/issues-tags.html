Round 2 mockup, for review. Uses your issue #141 and your three tag types. Click Edit and Back, open Appearance and change overrides to see the node update, and add a type under Tag types. Nothing here touches your data.

1 · Click a tag in the graph → issue view in the right panel

2 · Edit → the same panel, Appearance collapsed

3 · ⋯ menu → Tag types… (a dialog)

4 · What the graph draws

What changes

  • Issue view: clicking a tag still selects its bookmarks in the queue, and the right panel now shows the tag to read: type, status, link, description (with bold and lists rendered), and its bookmarks with the reason each one belongs. Clicking a bookmark there opens it. Copy… copies the issue's bookmarks; Edit opens the form.
  • Appearance is a collapsed section in the editor, with a live preview of the node. An unchecked field shows the value it inherits from the type.
  • Overrides change the node: color fills it, size and shape change it, and the icon is drawn inside it. Today only the border color updates after the first draw.
  • Tag types: a new “Tag types…” item in ⋯ lists every type with its node, tag count, and Edit. New type sets a name, color, shape, size, and icon. The tag editor's type list ends with “New type…”. The filter bar's type toggles follow automatically.
Types can't be deleted in this mockup, in line with “no deletion of bubbles or tags”. Should an empty type (no tags) be deletable?
