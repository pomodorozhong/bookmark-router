# Product

What Bookmark & Tag is for, what it deliberately leaves out, and how it behaves today. Work in progress and known gaps are in [HANDOFF.md](../HANDOFF.md) and GitHub issues; v1's build history is in [the v1 rounds](archive/v1-rounds.md).

## What the app is for

1. **Triage bookmarks.** Work through a Raindrop export one bookmark at a time and decide what each one is for.
2. **Group them into project ideas.** A bookmark joins one or more groups (existing GitHub issues, proposed issues, topics), and a group can be read as a whole.
3. **Let an agent help, through WebMCP.** The agent can add new items, fill in item details, and read processed groups with their bookmarks.

**Filters** support all three: finding what is left to triage and what belongs together. Anything not serving these jobs is frozen or cut.

## Scope boundaries

| Feature | Decision |
|---|---|
| Graph, import wizard, backup/restore, current Undo | Keep; fix bugs as found. |
| Copy composer | Triage selection/list/current copy with templates, presets, and preview. |
| Media upload and bulk status propagation | Frozen; old dialogs were removed in round 1. Existing backup media support remains. |
| C.1 undo rework (change sets, Redo) | Cut. Current Undo stays until it causes a real problem. The rename's schema version 2 does not implement C.1. |
| Record lifecycle | Collections can be deleted with confirmation and a backup offer. Bookmarks, tags, and tag types have no individual deletion. Archive/unarchive is not implemented. |
| Single bookmark creation | **Add bookmark…** opens a small dialog with URL and an optional title; an empty title becomes the site name, and a bare domain gets `https://`. The bookmark goes to To triage with Undo; a link already in the collection is named instead of added. **Import many or from a file** opens the import wizard. Agent creation is covered in [WebMCP](webmcp.md). |
| Advanced filter rules | Linked tag status, same-group, distance, and nested any/all remain in the domain engine but are not exposed by the compact filter UI. |
| Performance | Only if the real collection is slow. The 148-bookmark collection does not need the former 5,000-bookmark budget; 1,000/5,000 measurements and release review are cut. |
| Static deployment (GitHub Pages) | The `Pages` workflow builds `app/` and publishes it to `https://pomodorozhong.github.io/bookmark-router/` on every push to `main` ([#17](https://github.com/pomodorozhong/bookmark-router/issues/17)); the repository's Pages source must be set to GitHub Actions. It has no bundled fetcher, so thumbnails come from keyless CORS services and are stored locally; a local agent reaches the app through a WebMCP relay. Collections are per origin, so a deployed copy starts empty until a backup is restored. |

## Current behavior

- **Map canvas** ([#93](https://github.com/pomodorozhong/bookmark-router/issues/93)): the graph fills the window and everything else floats over it. A header card along the top holds the collection menu, the bookmark-state picker and search, the filter menus, Undo, Agent and More. The graph tools sit under the collection menu, the bookmark or tag card on the right, and the queue as a strip of cards along the bottom. The bookmark-state picker filters both graph and queue; nothing is current until a bookmark is picked. Done, Drop, and membership changes save with labeled Undo feedback. Framing centres in the part of the graph the floating parts leave uncovered.
- **Graph tools:** one plain card with **Empty tags**, **Re-layout**, and **Reset…** (confirmed; also clears pins). Labels collapse to icons below 1180 px, and the row wraps between controls on narrow screens without scrolling. The bookmark count sits at the map's bottom left above collection progress; framing and zoom are a vertical stack in the bottom-right corner (zoom is hidden on phones, which pinch instead). Toggles that are on show teal text instead of a fill.
- **Filter menus:** three labeled menus beside the search: **Bookmarks** (Filter bookmarks, Highlight bookmarks), **Tags** (Show tag types, Hide single tags, Edit tag types) and **Views** (Saved views, Reset search and state). Each menu button names what it acts on and counts its active rules; picking an item opens its panel in place, with a back link to the menu. Every top-bar menu shares one style: 36 px rows, neutral hover, shared section labels. Copy remains in the queue. Filter supports Status, Tag, Tag type, Domain, Has, Import, and Added month, with option search/counts and Not. Values within a rule combine with OR; rules combine with AND. Untagged bookmarks means bookmarks with no visible tag, including memberships in hidden tags. Existing date/search semantics are retained.
- **Tag visibility:** By type hides a type's tags and their links while keeping bookmarks eligible under their other rules and inclusion settings. By tag is searchable and paginated, with Show, Hide tag, and Hide tag + bookmarks. The last choice excludes the union of all associated bookmarks, including overlapping memberships. Type hiding wins over Show, with a visible explanation. Explicit hiding applies to the graph, queue, and value counts. Reading a record outside scope does not reveal hidden tags or expand the graph; hidden tags of the current bookmark no longer peek.
- **Combined Saved views:** named save/load/delete covers search, bookmark state/rules/inclusion, type/tag visibility, per-tag bookmark exclusions, and highlights. Baselines without filters can be saved, including with Enter. Commands, persistence, backups, and Undo carry these settings without changing collection records or resetting node positions. Legacy views restore their original filter and individual hidden tags while preserving settings absent from that view. Reset search and state clears only search and returns to To triage, preserving bookmark rules, visibility, highlights, selection, and arrangements.
- Links keep a width in screen pixels, 1.2 px at 100% zoom, at least 1 px zoomed out and at most 1.8 px zoomed in, so a zoomed-out graph still shows its structure. Every graph color (nodes, titles and their backings, links, the pin) comes from a `--color-graph-*` or `--color-pin*` theme role in `styles.css`, and the graph redraws when the theme changes. The theme uses warm stone neutrals, one teal accent and an orange highlight, and has a dark appearance that follows the system setting.
- Clicking a group selects its bookmarks clockwise around the group, starting at the cluster edge when more than 90° of the ring is empty; the issue view uses the same order. J/K and arrow keys wrap through the queue. Keyboard shortcuts show as key badges on the buttons they trigger, hidden on touch screens: Q, C, F, /, K, J, Esc, D, X, S, and O, which opens the current bookmark's link.
- Issue views show descriptions, links, bookmarks, and membership reasons. Tag types can be created and edited. Appearance has four flat tag styles in eight directions, color presets/custom colors, size, and icons; titles always sit below tags, with no automatic initials.
- On phones and small tablets (820 px and below) the header is two rows: the collection name with Undo, Agent and More, then bookmark state, search and one **Filters** menu that holds the Bookmarks, Tags and Views sections. Above 820 px the three labeled menus sit beside the search. At every width the header controls are plain, without grey fills. Collection-wide processed/total, percentage, and To triage/Done/Dropped counts live in a subtle progress line above the queue and update after processing and Undo.
- At 820 px and below the import screen's header takes the same phone layout: no logo, a collection name that shortens to fit, an icon-only Undo, and **Agent** as one button, so nothing runs past the screen edge.
- The queue is a horizontal strip of cards with thumbnails, under its label, count and Copy. **Q** hides the strip down to its label and shows it again. On phones the strip sits under the header and the bookmark or tag card becomes a bottom sheet. ‹ › in the bookmark bar step through the queue, and J/K or the arrow keys wrap through it.
- Above 820 px the queue (rail, drawer or column) shows no key badges; Q, C and Esc still work there. The badges show only in the phone layout.
- The bookmark and issue panels open with a fixed bar: the link on the left, truncated with an ellipsis, and Copy, Edit, Pin, and close on the right. It stays in place for any title length and while the panel scrolls. Under the title, a thumbnail block shows the cover at 16:9, sized to the panel, beside where it comes from, **Find online** and the Microlink count. Done and Drop fill the decision bar; Deselect joins them only during a box selection. A tag's name in the Tags list opens that tag's view, and **Back** or Escape returns to the bookmark. Related bookmarks names the shared tag only when the bookmark has more than one. On phones the description follows the title, and on phones 760 px tall or less the panel takes 60% of the height while a bookmark or tag is open.
- The tag view and Related bookmarks group their bookmarks as To triage, Done and Dropped, by the same rules as the queue tabs, each under a heading with its count and a Copy button that opens the Copy dialog with just that group. Inside each group the tag view keeps the box selection's clockwise order and Related keeps its most-shared-first order. The editor's Status list offers To triage, Done and Dropped; a record with another open status, such as In progress, shows and saves as To triage.
- Bookmarks and tags have Pin/Unpin. Pins survive bookmark-state layout changes and reloads; only **Reset…** in the graph tools clears them. A reset lays out the shown nodes plus the hidden tags of shown bookmarks, undrawn, so a hidden type's bookmarks stay grouped around the spot its tags return to; other hidden nodes get free spots beside their links. Pin controls wait for the graph to become ready.
- **Highlight by tag** ([#89](https://github.com/pomodorozhong/bookmark-router/issues/89)): **Highlight bookmarks** sits in the Bookmarks menu (the Filters menu on phones). It stages one or more tags, Any/All, a preview count, Cancel, and Highlight. Its menu also holds active-tag removal, shown/hidden counts, Fade the rest, and Clear. Removing an active tag updates the staged selection. Matches get orange rings/glows without filtering or reranking; the bookmark panel identifies matches. Fade remains a device preference, and named Saved views now also carry highlight tags, matching mode, and fade.
- Collections can be deleted with confirmation and a backup offer. Bookmarks, tags, and tag types cannot be individually deleted; archive/unarchive is not implemented.
- **Agent review** (round 4) was approved October 14, 2026; its accepted behavior and verification are documented in [WebMCP](webmcp.md).
- **Agent imports** ([#84](https://github.com/pomodorozhong/bookmark-router/issues/84)): an agent can propose a complete new collection, with tags, bookmarks, descriptions, and thumbnails, through `propose_import`. Agent review shows it summary first, with totals, tag counts that filter the list, and expandable bookmarks. It stays reviewable from any collection until the tab reloads. **Apply import** creates the whole collection in one save and opens it; Undo leaves it empty. See [Complete collection imports](webmcp.md#complete-collection-imports).
- **Batch tag** ([#88](https://github.com/pomodorozhong/bookmark-router/issues/88), [#94](https://github.com/pomodorozhong/bookmark-router/issues/94)): every agent batch gets one tag by default, named by the date and the agent's summary ("2026-10-26 · Monetization and pricing research"), or the date and time when the agent gave no summary. It shows as a chip on its own line under Agent review's summary, with one gray line explaining it; **×** skips it and leaves a dashed **+ Batch tag** in its place. An edit batch tags the bookmarks it adds, or the ones it updates when it adds none; an import tags every bookmark. Batch tags belong to the **Import** tag type, created when first needed and hidden in the graph by default (Show › tag types brings it back); an Import tag with the same name is reused. The tag stays with the proposal in the tab, survives Set aside and Close, and is saved only by Apply, as part of the same Undo action. The agent never sees or sets it.
- **Highlight this batch** ([#94](https://github.com/pomodorozhong/bookmark-router/issues/94)): after applying an edit batch with its tag, the toast offers **Highlight** beside Undo, and the applied batch in Agent review offers **Highlight** next to the chip. Either replaces the current highlight with the batch tag and keeps Fade the rest; the review's button is disabled once Undo removes the tag. Imports have no shortcut, since every bookmark in the new collection carries the tag.
- **Thumbnails** ([#7](https://github.com/pomodorozhong/bookmark-router/issues/7)) are stored locally. Per-bookmark lookup names the outside services before sending, and bulk lookup defaults off. Captures survive Undo and backup/restore, retain imported covers, and refresh only on manual retry. See [thumbnail behavior and verification](thumbnails.md#implementation-and-verification).
- **Agent** is one icon button at every width. Its menu opens **Agent review** (a dot on the icon marks a waiting batch) and owns the opt-in loopback relay switch and status; **More actions** stays focused on collection operations. The page-side relay was verified on a disposable `127.0.0.1:5201` origin with six tools discovered and removed again when the switch was turned off.
- Menu settings are rows with a switch at the end: **Find thumbnails online** in More actions (turning it on still asks first), and **Connect to a local agent** in the Agent connection menu, which shows the connection state once, beside its switch. A status card under it appears only while searching for the relay, once connected, or after a failure.
- The app is **Bookmark & Tag**. Backups use `bookmark-tag` version 2 and browser storage uses `bookmark-tag`. Old `bubble-tag` version 1 backups require `npm run upgrade-backup`; there is no in-app upgrade.
